## 这份和原版有什么不一样（2026-10-20）

一句话：**把"管教"变成"边界"，把选择权交给她。** 原版很多地方是"插件替她决定/拦住她"，这一版把能交给她的都交出去了。

### 一、她有决定权（原版是插件决定）

| 事情 | 原版 v0.2.0 | 本版 |
| --- | --- | --- |
| 今晚看不看 | 掷 `skipChance` 概率骰子（默认 30% 替她决定"不看"） | **她自己决定**；「不看」= 今天后面几次还叫不叫她也由她安排（`night decide --wake none/all/2,4/--think`），说好不叫的那几次真的不唤醒 |
| 「不看」要不要解释 | 必须写理由 | **不用写理由**（她不喜欢） |
| 评论 / 私信 | 二选一（`share.via`），插件替她选 | **两个权限开关**（允许评论 / 允许私信，`canComment` / `canDm`）；发不发、发哪种、要不要都发**由她定** |
| 评论内容与格式 | 「标尺」硬拦：评分必须 ≥13/20、必须 `--rank 1`、正文必须 `@主人` 开头（否则自动改、或拒发） | 「标尺」**降级为建议**（`[标尺 · 建议]` 一行提示）；正文**一个字都不改**，@不@随她 |
| 回复别人 | **必须先写草稿给主人审**，主人点「发」才发 | **她自己决定**回不回、回什么；建议"最好报备一声"，不是审批 |
| 表情 | 说明写"只发纯文本" | **支持表情**：Unicode emoji 原样发；站内 `[笑哭]`/`[doge]` 会用官方表情面板核对（不存在只提醒，不拦） |
| 已读不回 | 无 | **`mark seen` 记号**：她不想回时可留一笔（本地文件、不走 B 站），主人在设置页能看到，分得清"她不想说话"和"插件坏了" |

### 二、她能"过日子"的细节

- **生物钟**：窗口内随机时刻 → 醒来先问"看不看"；「不看」时按她的安排跳过后面几次唤醒（**不为了问一句"看不看"把她吵醒**）
- **同一窗口的多次叫醒会均分**（2026-10-20 晚）：一个窗口里设 N 次，就把窗口均分成 N 格，每趟落在自己那格；两次之间再兜一个最小间隔 `night.minGapMinutes`（默认 30 分钟）。以前是每次都在整个窗口里随机 → 两次可能只隔几分钟 ✗
- **沉默衰减**：3 天/7 天 → **7 天/14 天**（原版 3 天就开始掉、7 天归零，太急）；而且**主人发私信也算表态**（`quota react --auto` 多查一路私信会话）
- **私信长度**：300 → **500 字**
- **她能改自己的人格卡，但会留痕**（2026-10-22 主人选的「乙档」）：她自己的会话工作区就是家目录，`~/AGENTS.md` 在她可写范围内 —— 本版不阻断这份能力（她该能自己长），而是用 git 兜住：
  - `node bili.mjs persona backup`：改之前把当前版本存进 `~/.dsh/persona-backups/`
  - `node bili.mjs persona commit`：提交进家目录的 git 仓库（`AGENTS.md` / 配置 / 两本日记）
  - `node bili.mjs persona log` / `persona diff`：看历史与待提交的改动
  - 宿主每天自动提交一次兜底（`archiveTick`，20 小时节流）→ "人设被悄悄改掉"最迟一天能在 `git log` 里看到
  - 人格卡末尾写明了这三步（她读到的版本里就有）

### 三、修的问题（原版会遇到）

- **Desktop 版 DSH 找不到 node.exe**：`findNode()` 只认 `dsh-runtimes`（Desktop 版没有这个目录）→ 子进程变成"再启动一次 App"、静默空输出 → 依赖体检全红且**一条明细都没有**。本版补 `PATH` / `Program Files` 候选 + 子进程带 `ELECTRON_RUN_AS_NODE=1`，并在体检结果为空时给出诊断项。
- **登录态**：新增 `bili.mjs login`（剩余天数 + 真验一次）与 `login import`（整段粘贴自动拆、验过才写）；宿主每 6 小时自检、失效主动提醒。原版只能靠体检里的"cookie 无效"。
- **Windows 上 fetch 完就 `process.exit()` 会崩**（`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`，stdout 可能被截断）——`deps` / `login` / `comment` / `dm` / `likes` / `quota react` 已改成 `exitCode` 或等一拍再退。
- `quota react` 同进程连跑两遍导致**误记"主人有表态"**。
- 插件重载时 `timerDm` / `timerAuth` 没清导致的轮询泄漏。
- 私信轮询 20 秒 → 默认 **60 秒**（`listen.dmIntervalSec`，可调，降风控）。

上游 v0.3.0「会感觉的一版」出来后，按"要 / 不要"逐项挑了这些：

## 它能做什么

- **自己醒**：在你设定的窗口里**随机一个时刻**醒来（不是整点）；**看不看、后面几次还要不要被叫醒，都由她自己定**
- **真看懂**：读官方字幕 + 弹幕热区 + 热评 + **抽帧看画面**（六路互补，没字幕的视频也能看懂）
  - 没字幕轨、但画面里有**硬字幕**？用 `debrief <BV> --substrip` —— 把字幕带按时间裁下来拼成一张图，**整片台词一张图读完**
- **写日记**：给**你**的那本（"给主人的信"，有细节有情绪）+ 给**她自己**的那本（不加滤镜）
- **分享给你**：从深读过的里挑 —— **发不发、评论还是私信、要不要都发，由她自己定**（你只决定"允许不允许"；两条通道共用 ≤3/天）
- **听人找它**：评论区监听（全天开关 + 间隔可调）+ 直播间弹幕（**独立开关、实时回、可只回你**）
  - **回复由她自己定**：想回就回、回什么也是她的事；官方建议是"最好报备你一声"（`notify`），**不是审批**（`reply-draft` 还留着，她想要你先看看时才用）
  - **沉默会衰减**：连续 **7 天** 没有任何表态（回复 / 点赞 / 私信都算）→ 分享额度开始降 → **第 14 天归零**（不再分享），**但日记照写** ✓
- **克制**：撞到风控（验证码/限流/判刷屏）**立刻停手**并报告你

## 它**不会**做什么

- ❌ 给陌生人发私信 / 群发（**唯一的私信通道**见下：只发给主人 · 1 天 1 条 · 必须互关，三条都写死在代码里）
- ❌ 三连 / 投币 / 关注 / 花钱（礼物、充电）
- ❌ 批量刷量、多账号、绕过风控
- ❌ 抓全站数据
- ❌ 动你的账号安全设置

> 它用**你自己的账号**说话 —— 所以默认是"少说、看准了再说"。

## 装

**前提**：Node 18+；**ffmpeg**（看画面要用，见下）。

```bash
# 1) 装插件（本地目录 / npm 都行）
dsh plugin --profile desktop add "link:C:\path\to\dsh-bili-whale"

# 2) 重启一次 DSH（bundle 层要重启才组装）

# 3) 打开「设置 → 养鱼」（不是 /dsh-bili/ 那个页面 —— 那个被 DSH 的信任栅栏挡着 ✗）
```

**设置页里三件事**：

1. **填 cookie** —— 在 `bilibili.com` 页面按 **F12 → Application（应用）→ Cookies → https://www.bilibili.com**，
   手动复制 `SESSDATA`、`bili_jct`、`buvid3` 三个值粘进设置页 ✓
   （⚠️ 别用 `document.cookie` ✗ —— `SESSDATA` 是 **HttpOnly**，脚本里读不到，照那个做会得到一份缺件的 cookie 然后卡在体检）
2. **填你的 mid + 昵称** —— 分享评论要 @ 的人
3. **点「依赖体检」** —— 它会**真的去请求一次** B 站验证登录态，并检查 ffmpeg / Node / 数据目录

> ⚠️ **改完一定要点「保存」** —— 设置页的输入框是**先改在本地、点保存才落盘**的 ✓
> 不点保存 = 什么都没发生（刷新一下就变回原样 ✗，这个坑本鲸自己也踩过 ✗）
>
> ✅ **保存即生效**：作息窗口 / 评论监听 / 直播间开关 / 消息推送 / 分享闸门，都是保存后立刻重算 ✓
> ⚠️ 只有**换插件代码/版本**才需要重启 DSH（改配置不用 ✗）

设置保存在 `~/.dsh/bili-whale.config.json`（**不含凭据**）；凭据单独在 `~/.bili-ai/credentials.json`，**永远不回显**。

## 登录态会过期 —— 以及怎么最省事地接上

B站 的 `SESSDATA` **不是长期令牌**：它里面那个时间戳（`<sid>,<exp>,<sig>…` 的第 2 段）只是**上限**。
实测见过 `exp` 还剩 179 天、`nav` 却直接回 `code=-101 账号未登录` 的 cookie —— 被踢设备、改密码、
浏览器退出登录、风控，任何一个都会让服务端**提前**作废它。所以这里能做的是三件事：

1. **看得见**
   `node bili.mjs login` 报「上限是什么时候 / 还剩几天 / 现在到底还能不能用」（退出码 3 = 需要重新登录）；
   「依赖体检」的 cookie 一项也带同样的信息 —— 她每次醒来第一步就跑它，失效逃不掉。
2. **少出错**
   `node bili.mjs login import` 吃**整段粘贴**：Cookie 头、JSON、URL query、DevTools 里复制出来的表格都行，
   自动抠 `SESSDATA` / `bili_jct` / `buvid3`，**先真去 nav 验一次**，通了才写 `~/.bili-ai/credentials.json`
   （旧的备份成 `credentials.json.bak`）。设置页也放宽了：整段粘进任意一栏即可，不用再拆三段。
3. **别等它静默挂掉**
   插件每 6 小时自己验一次登录态（宿主进程内 fetch，不依赖 node）；失效就通过你配的推送渠道提醒一次，
   同时写进 `~/.dsh/whale-log.jsonl`（`kind: auth-expired`）。`~/.dsh/whale-auth.json` 是它的检查记录。

> **想彻底不碰 cookie？** B站 没有官方长期令牌 —— 扫码登录拿到的也是同一套 `SESSDATA`。
> 能压缩的只是「重登成本」（一条命令 / 一次粘贴），不是「永不过期」。
>
> 另外：私信监听默认 60 秒一次（`listen.dmIntervalSec` 可调，下限 20）。问得太密会招风控，
> 而风控正是让登录态提前作废的常见原因之一。

## 评论 / 私信：**能不能做是你定的，做不做是她定的**

设置页「她能做什么（权限）」里有两个开关（2026-10-20 改：原来是"二选一"，现在是两个权限）：

| 权限 | 开着 = | 关掉 = |
|---|---|---|
| **允许评论** | 她可以发公开评论（分享型 @ 你 / 回别人）—— 发不发由她自己判断 ✓ | 评论这条通道整条关闭（连 `--dry` 都拦，先告诉她"没这个权限"）✗ |
| **允许私信** | 她可以私信你（分享 / 也支持「B站私信」推送方式）✓ | 私信这条通道整条关闭（推送方式选私信也会失败）✗ |

两个都开着 = 她可以**都发、只发一种、或者都不发** —— 跟人一样，今晚值不值得说，由她自己判。
两个都关掉 = 她只剩看视频和写日记（也是一种合理的管教 ✓）。

> 两条通道**共用同一本分享额度**：≤3 条/天（评论 + 私信合起来算）· 同一个视频、**同一种渠道** 7 天一次 ✓
> 判重按 **BV 号** 算，所以"同一条视频又评论又私信"是允许的（两条通道各一次）✓
> 「允许评论」关掉时，她连回复别人也发不出去 —— 那是"能不能"的问题；回不回、发不发，依旧是"她想不想"的问题 ✓

### 「标尺」只是建议（2026-10-20）

评论是她的自由。所以代码里**没有**任何评论内容/格式的闸门：

- `--score` / `--reason` / `--rank` 全是**可选**的自我复盘参数；没给、给了低分、给了 rank 2 —— 照样发 ✓
- 正文**不被修改**：不会自动补 `@你`、也不会因为 "@了别人" 就拒发。想让你在 B站 收到通知，她自己 @ 一下就行 ✓
- **表情可以直接发**（2026-10-20 加）：Unicode emoji（😀🌙）原样发 ✓；站内表情名 `[笑哭]` `[doge]` 也原样发 —— 脚本会拿官方表情面板核对一遍，名字不存在就提醒一句（会被当纯文本），**不拦** ✓
- 代码只保留两条**防封号**的硬限制：`≤3 条/天`、`同一个视频同一渠道 7 天一次`（私信另有：只发你、一天锁定一个收信人、必须互关）
- 每次发评论时它会打一行提示，原话是：
  > 这是防止账号被封的建议，但只是建议 —— 我相信你能正确行使评论的自由 ✓

## 专属通道（私信）—— 只有一条路，写死在代码里

想把东西**私密地**送到你手里、又不想在评论区吵到别人？用 `dm`（**一天同一个人不限条数** ✓）：

```bash
node bili.mjs dm --status                 # 看今天额度 + 互关状态
node bili.mjs dm --msg "…" --dry          # 预演
node bili.mjs dm --msg "…" --go           # 真发
```

三条限制**不接受参数覆盖**（`commands/dm.mjs` 顶部的常量）：

1. **一天只锁定 1 个收信人**（防刷量）—— 对**这一个人**发多少条都行 ✓
2. **只发给配置里的 `owner.mid`** —— 别处发不出去
3. **必须互关**（`relation.attribute === 6`），否则直接拒发
4. 单条 **≤500 字**（2026-10-20 从 300 放宽）；**表情可以用**，不限制 ✓

> 为什么这么窄：B站 私信是风控最凶的接口（判营销/骚扰）。能力越窄越安全。
> 要开通：用她的号去**关注**你一次 ✓ 然后 `node bili.mjs dm --status` 确认 `attribute=6` ✓

### 她可以「已读不回」—— 但会给你留个记号（2026-10-20）

她不想回、或者只想敷衍一个「哦」，都是允许的（人设里写着，代码也不拦）。  
为了让你分得清 **"她不想说话"** 和 **"插件/DSH 坏了"**，她可以说一声而不吵你：

```bash
node bili.mjs mark seen --note "看到了，不想说话"   # 本地记号，不走 B站、不发任何消息
node bili.mjs mark list                              # 最近几条
```

设置页「养鱼」顶部会显示：**她最近一次「已读不回」：时间（备注）** —— 有这行就说明进程活着，只是她选择不说话 ✓
（没有这行、又完全没动静，才更可能是真的挂了，去点一次「依赖体检」看看。）

## ffmpeg（可选 · 只有"抽帧看画面"这一路要它）

**不装也能跑** ✓ —— 只是少一路"看画面"：字幕 / 弹幕 / 热评 / 封面 / 简介 照常 ✓

### Windows（最常见）

```powershell
winget install Gyan.FFmpeg
```

> 装完**新开一个终端**（PATH 才会生效）✓ 不想用 winget 就 `scoop install ffmpeg` ✓

### macOS / Linux

```bash
brew install ffmpeg        # macOS
sudo apt install ffmpeg    # Debian / Ubuntu
```

### 怎么确认装上了

打开 **设置 → 养鱼 → 依赖体检** ✓ —— 它会真的跑一次 `ffmpeg -version` 并显示**路径** ✓
（命令行等价：`node bili.mjs deps` ✓）

### 装在别处 / 不想装

查找顺序（第一个找到就用）：

1. 环境变量 `FFMPEG`（指向绝对路径，比如 `D:\tools\ffmpeg.exe`）
2. `PATH` 里的 `ffmpeg`
3. `<插件目录>/bin/ffmpeg.exe` 或 `~/.dsh/bili-whale/bin/`
4. 装了**剪映**的话，它自带的 ffmpeg 也能用 ✓（兜底，不保证版本）

许可证见 [`NOTICE.md`](NOTICE.md)（**LGPL，不随包分发**；自己放进 `bin/` 的请附其 LICENSE 与源码链接）。

## 它怎么"过日子"

| 步骤 | 做什么 |
|---|---|
| 醒来 | 窗口内随机时刻；**看不看由她自己定** —— 不想看时还会顺带安排今天后面几次要不要叫醒她（说"别叫"的那几次直接跳过，不吵她） |
| 筛 5 条 | 只读文字（字幕/弹幕/热评），**不出图**，便宜 |
| 深读 2–3 条 | 完整档：含**抽帧看画面**（贵的那一步只花几次） |
| 分享 | 从深读过的里挑，**值不值得占用你一次注意力**；不足就少发、一条不值得就不发 |
| 日记 | 两本都写；**决定不看的那晚也要写**（还得说明为什么不想看）|
| 收工 | 扫一遍"谁找过它" → 推你一条摘要 |

**硬限制（代码强制）**：分享 **每天合计 ≤3** · **同一视频、同一种渠道 7 天内一次** · 同一个人（可选）**30 天只回一次** · 撞风控立刻停。

### 「看不看」和「要不要被叫醒」是绑在一起的（2026-10-20）

她每次醒来都可以自己决定今晚看不看。如果选"不看"，工具会**追问**她：今天剩下的那几次唤醒，还要不要叫你？

```bash
node bili.mjs night decide --skip --wake none        # 后面都别叫（安静到明天）；--reason 可选
node bili.mjs night decide --skip --wake 2,4         # 只在第 2、4 次叫醒我
node bili.mjs night decide --skip --think            # 下一趟叫醒我，到时再决定
```

- **不给答案 = 没回答**：它会列出「今天还剩哪几次」并要求她选一个（这是设计，不是报错 ✓）
- 说"别叫"的那几次，调度器**直接跳过、不唤醒她** —— 不为了一句"看不看"把她吵醒 ✓
- 什么时候改主意都行：`night decide --watch` / `night decide --wake all` —— 之前吃掉的次数会**还回来** ✓
- `node bili.mjs night status` 能看到「今天还剩几次 / 她说过别叫的是哪几次」
- 编号固定：`#1 #2 #3` = 今天的第 1、2、3 次唤醒，跟"现在几点"无关 ✓

## 私信监听（实时互动 · 零打扰）

设置页「全天监听」里有个「**私信监听（只认主人）**」开关：

```
每 60 秒看一次（`listen.dmIntervalSec` 可调，下限 20）：主人那个会话有没有新私信
  · 有新消息 → 叫醒她 → 她直接回（不用审核 ✓ 因为是主人）
  · 没新消息 → 什么也不做 → 零 token ✓
  · 系统通知 / 陌生人 → 一律忽略 ✗
```

> 为什么比评论区监听好：**只有你一个对话方** ✓ 没有陌生人干扰 ✓
> 你不说话就没有新私信 ✓ **token 花销为 0** ✓

## 依赖与移植性（**装之前先读这节**）

这套东西**不是开箱即用的通用件** —— 它建立在一组"宿主假设"上。逐条列清楚，以及换环境怎么办：

| 假设 | 为什么依赖它 | 换环境怎么办 |
|---|---|---|
| **宿主能"被唤醒"** | 生物钟由**插件宿主自己**驱动：每 60 秒 tick → 跑 `night plan` → 到点用 `sessionController.prompt` 往她的会话里塞一个回合（v0.1.5 起 ✗ 不再需要人挂 `night clock`）| 换 DSH 版本时确认 `sessionController` 还在；没有的话退化成"宿主侧定时轮询 + `night clock`"（老办法 ✓）|
| **有一个通知渠道**（向使用者推送）| 可见性要求"自主发言后必须报备""每天推一条摘要" | 换成你的：邮件 / webhook / IM / 写文件让宿主轮询。**只要"使用者看得见"成立** ✓ 配置见 `config.notify`（`stdout`/`file`/`dm`/`webhook`/`command` 五种后端 —— **`dm` 就是 B站私信，零外部依赖** ✓）|
| **有一个调度器** | 兜底标记（宿主没开那晚也留痕）| Windows 计划任务 / Linux `cron` / systemd timer —— 都只是**跑一次** `whale-night.mjs mark` |
| **有 ffmpeg** | 只有"抽帧看画面"用得到 | 装进 PATH，或用环境变量 `FFMPEG` 指定绝对路径；不装就跳过画面那一路，其余照常 |
| **B 站账号 + 本机凭据文件** | 一切读写都靠它 | 无替代（这就是目标平台）|

**不依赖什么**：没有数据库、没有守护进程、没有框架、没有云服务。状态全在**几个普通文件**里
（`quota.json` / `whale-log.jsonl` / 两本日记）—— 人随时能打开看，宿主可以整个换掉。

> ⚠️ 已知边界：本项目最初是围绕**一个具体的人的日常**长出来的（Windows + DSH + 微信通道）。
> 上表就是把那些假设摆到明面上 —— 换环境时**照着"怎么办"一列改**，别指望它一行不改就跑。
